# Checklista: czy PRD jest gotowy dla agenta?

Recenzent czyta PRD **na ekranie autora** i odpowiada TAK / NIE. Każde NIE = jedna konkretna poprawka.
Pytania oznaczone ★ sprawdzamy na pewno (F4, 7 minut). Reszta — w domu.

| # | Pytanie | TAK / NIE |
|---|---|---|
| ★1 | Problem jest opisany faktami (liczby, sytuacje), a nie przymiotnikami („trudny”, „nieefektywny”)? | |
| ★2 | Każdy cel ma miernik i wartość docelową? | |
| ★3 | Jest sekcja „poza zakresem” z co najmniej 3 pozycjami? | |
| ★4 | Każda historia ma format „Jako… chcę… aby…” i co najmniej 2 kryteria akceptacji? | |
| ★5 | Historie *Must* to mniej niż połowa wszystkich historii? | |
| 6 | Kryteria akceptacji da się sprawdzić bez pytania autora (konkretne wartości, komunikaty)? | |
| 7 | Każda historia ma ID (US-01…), priorytet, rozmiar i przechodzi INVEST (`docs/INVEST.md`)? | |
| 8 | Zależności między historiami są zapisane („zależy od: US-…”)? | |
| 9 | Są zależności zewnętrzne i ryzyka z planem reakcji? | |
| 10 | Wymagania niefunkcjonalne mówią, jakie dane osobowe zbieramy, gdzie i jak długo? | |
| 11 | UI/UX zawiera stany: pusty, błąd, ładowanie? | |
| 12 | Kamienie milowe mają kryterium ukończenia? | |
| 13 | Otwarte pytania są zapisane, a nie „rozstrzygnięte” po cichu przez agenta? | |
| 14 | Osoba spoza projektu zrozumie PRD bez autora obok? | |

**Test ostateczny:** czy dałbyś(-abyś) ten dokument agentowi w chmurze i poszedł(-szła) na wykład?
